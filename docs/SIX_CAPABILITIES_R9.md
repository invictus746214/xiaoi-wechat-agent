# 小i六项能力升级设计

目标：在现有数据库事件流程上增加语音理解、可见可纠正的表情管理、更准确的群聊对象判断、短时合并发言、经同意的事情跟进，以及主人微信管理。

## 方案与边界

沿用 Python、SQLite 和唯一界面执行器。独立处理语音与媒体，避免模型或识别任务阻塞收发；可用的轻量本地识别优先，若需另配接口须明确显示未配置状态。禁止用聊天模型猜语音内容。

表情管理基于当前会话的可验证消息来源，分别报告原文件和原生收藏状态。纠正情绪标签不绕过素材隐私筛选，不重放结果未知的收藏或发送。

群聊区分被 @、引用小i、对其他成员说话与同一人的后续提问。连续发言只短暂等待，并有等待上限，不能占住其他会话或改变已有发送批次。

事情跟进只在用户明确同意后创建，保留原场景、去重、到期与取消语义。通过现有任务投递与回执流程执行，不直接在后台发消息。

管理只接受已验证的主人账号私聊。运行设置以 SQLite 覆盖层持久化，不允许模型改权限、写任意配置或执行命令；临时设置到期恢复，服务重启后仍能解释当前状态。

## 验收

1. 收到语音取得真实转写，并作为带来源的输入进入原有上下文；缺失、超时、失败均不编造。
2. 当前会话可以查询表情保存/收藏状态，并对自己的明确素材纠正受控标签。
3. 群友聊别人的话题时不误接，@和引用小i不被遗漏。
4. 短时连续消息合并处理，等待有上限，其他会话不受阻，旧草稿不重组。
5. 用户可同意、查询与取消一次事情跟进，只在原会话投递且有回执。
6. 主人可在微信调整主动接话、朋友圈互动和自动表情收集，其他人不能改变设置。

部署前运行完整回归与独立 Linux 验证，保留源码和配置回滚备份。公开版本不包含账号、密钥、聊天记录或媒体素材。
