# 开发交接

## 当前代码范围

本仓库整理自 2026-11-01 的 Linux 实例，包含数据库事件流程、群聊与身份记忆、回复规划、表情闭环及 r8 媒体可靠性修复。运行代码按 `SOURCE_SHA256.json` 核对，历史部署脚本和带账号信息的旧交接记录不纳入公开版本。

r8 修复特殊 WXGF 容器解码失败后的有界重试，保留 SPS/VPS 等参数并共享原有 12 秒时限；修复长方形图像匹配时的比例失真；收藏过程中在滚动、解码与回执等待阶段响应高优先级消息。解码后重新检查图像和最新入站媒体，避免沿用已过期的坐标。点击后让位仍按 `unconfirmed` 处理，不自动重放。

## 修改前必须保留的边界

1. 界面只能由一个执行器操作；模型工作线程不能直接点击微信。手工调试界面时先暂停服务，结束后恢复。
2. 动作前核对当前账号、唯一会话、消息来源和收发方向。不要仅凭固定坐标发送或评论。
3. 不点未知对话框的 OK，不在主窗口按 Escape，不使用 AT-SPI action 点击，不用剪贴板填写朋友圈评论。沿用已验证的 XTest 输入方式。
4. `sending` / `unconfirmed` 不自动重放。先查微信原生记录或发送回执；本地动作返回成功不等于对方收到。
5. 不修改微信原始数据库。读取快照和缓存使用与客户端一致的用户，避免生成 root 专有缓存权限。
6. 不打印聊天正文、密钥、联系人清单和全屏截图；测试与问题报告只保留必要的脱敏元数据。
7. 媒体读取或视觉失败不能阻塞普通文字消息；保留新消息优先、私聊处理容量和任务超时。
8. 跨场景共享普通身份、称呼与兴趣时保留身份置信度；不要把私聊详情当作群聊事实。

## 表情处理状态

收到 type 47 消息后，校验账号、来源及媒体哈希，优先获取原文件。动态格式解码多帧后交视觉理解，筛选可复用素材并去重保存。原生收藏必须匹配正确的源图，并从微信收藏记录确认；发送也要核对新的原生消息回执。

素材筛选、服务器保存、微信收藏、原生发送分别记录状态。不可因“功能已开启”就回复“这张已收藏”；私人图片归档也不等于可跨聊天复用。

最近一次批量操作已独立校验 36 个原文件，原生收藏确认 19 个，另外 17 个尚未确认加入原生收藏。该批次的账号、原文件及详细清单留在私有实例，不上传本仓库。这是后续需要继续改进的定位场景，不能宣称批量原生收藏已全通过。

## 后续优先事项

- 提高历史表情的精确定位，稳定区分相似表情、裁切行与未完全下载的原文件。
- 把桌面布局变化和焦点丢失当作明确失败，避免不断增加固定坐标兜底。
- 持续检查繁忙群聊是否占用私聊容量，以及新消息能否越过旧积压。
- 用真实收件端验证图片、动态表情、分条发送、群内 @、跨场景身份与朋友圈评论。
- 保持发布副本与私有部署状态分开；回滚源码不回滚回执数据库，避免旧动作再次执行。
- 启动时的旧记忆兼容扫描会延迟执行器就绪，当前实例约需 40 秒；后续应改为可恢复、按需执行，健康检查需区分进程运行与账号已就绪。
